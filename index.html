Woo Order Archive Manager
Plugin Development · Database Optimization Open Source v1.0.0

WooCommerce order tables are a silent performance killer. Stores accumulate hundreds of thousands of rows over time — slowing down admin pages, checkout queries, and analytics reports. This plugin physically moves completed orders into dedicated archive tables using MySQL transactions, so live tables stay lean and stores stay fast.

Transactional archiving — every order is copied row-by-row inside a DB transaction. If anything fails mid-copy, the transaction rolls back automatically and the source data remains untouched.
Verification layer — row counts are checked between source and archive tables before a single live row is deleted. No match means no delete, no exceptions.
Dry-run mode — runs the full archive cycle inside a transaction and rolls it back, giving a preview of exactly what would change with zero risk to live data.
Health score engine — a weighted 0–100 score computed across DB size, table integrity, archive coverage, and growth rate. Cached via WP Cron and refreshed automatically every 6 hours.
Onboarding wizard — scans the store on first run and shows total orders, archive candidates, and estimated DB space savings before the user takes any action.
WooCommerce Subscriptions guard — renewal orders and orders linked to active subscriptions are automatically skipped to prevent billing chain breakage.
Full restore — archived orders can be moved back to WooCommerce at any time with original IDs, line items, meta, notes, and refunds fully intact.

Multi-Biometric Voter Fraud Detection
Python · Django · Biometrics Python

A full-stack biometric authentication system built to prevent electoral fraud. Voters are registered with three independent biometric identifiers — iris pattern, facial geometry, and fingerprint — all stored securely in a database. At the time of voting, live captures from dedicated hardware devices are matched against the stored records to verify identity and prevent any individual from casting a duplicate vote.

Triple-factor biometric matching — iris, face, and fingerprint are each verified independently, requiring all three to pass before a vote is accepted. A single mismatch blocks the attempt.
Voter registration pipeline — a structured Django backend handles voter enrollment: biometric data is captured, processed, and stored in a normalized database schema with unique constraints per voter.
Real-time matching at the polling booth — live captures from iris scanners, fingerprint readers, and cameras are processed on-device and compared against stored templates using computer vision libraries.
Duplicate vote prevention — once a voter's biometrics are matched and a vote is recorded, the system marks that voter's record as cast and rejects any subsequent attempts from the same identity.
REST API backend — Django REST Framework powers the voter verification endpoints, with a clear separation between the registration flow, the verification flow, and the admin interface.
Frontend + backend architecture — the project is structured into dedicated backend, frontend, and database layers, with a render.yaml for deployment and a managed requirements file.
